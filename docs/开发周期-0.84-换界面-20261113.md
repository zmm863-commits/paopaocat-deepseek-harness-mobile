## 1. B 路线：两套新皮肤

### 1.1 改了什么

`app/lib/ui/theme/dsh_palette.dart` 新增两个实例并注册：

- `lucian-light` → 显示名 **泡泡白**（暖白纸底 + 紫罗兰强调）
- `lucian-dark` → 显示名 **泡泡夜**（近黑底 + 淡紫霓虹）

注册点三处：`byId()` 加两个 case、`all` 列表加两项、设置页的皮肤按钮是
`for (final p in DshPalettes.all)` 自动画出来的，**没动页面代码**。

### 1.2 色值从哪来、为什么不是照抄

色值来自 **Lucian UX/UI Prompt 的 `--ux-*` 主题令牌**
（MIT License (c) 2026 Seokwoooo，https://lucianlabs.dev/uxui-prompt/）。

**可行性判断**（这是本条的全部依据）：该库的 400 个元素是纯 HTML/CSS/JS，
Copy prompt 只会被 AI 移植成 React/Vue/Svelte，**不会变成 Flutter Widget** ——
所以元素代码一行都不能直接用。但它的**色板是标准 CSS 变量**，按名逐条映射到
`DshPalette` 字段是等价替换；曲线 `cubic-bezier()` 是标准定义，坐标原样换算成
`Cubic()`。结论：**色值与动效参数可换算使用，组件代码全部在 Dart 里重写。**

许可证：本项目 MIT、该库 MIT，**代码不互用**（AGPL 才有传染性，这里是 MIT↔MIT，
但仍然只取"可换算的参数"，不取实现）。按项目规矩，技术文档不写取用关系，
只写可行性判断。

### 1.3 与原令牌的四处有意偏离（都为过 WCAG AA）

`contrast_test` 遍历 `DshPalettes.all`，要求 text / textDim / textFaint / accent /
busy 在 **bg 与 bgSoft 两块底**上都 ≥ 4.5。原令牌有四处不达标：

| 令牌 | 原值 → 采用 | 原对比度 → 采用 |
|---|---|---|
| `--ux-accent` | `#6A57F2` → `#5F4EEB` | 4.41 → **4.97 / 4.80** |
| `--ux-ink-3` | `#8E8A97` → `#686472` | 3.01 → **5.14 / 4.96** |
| `--ux-warn` | `#D6731E` → `#9A5712` | 2.97 → **5.01 / 4.84** |
| 次级底 `bgSoft` | 原计划 `#EAE7E1` → **`#F1EEE8`** | 见下 |

**`bgSoft` 这条是被测试逼出来的**：首轮我按 `--ux-surface-3` 取了 `#EAE7E1`
（比底实一档，方向与旧浅色皮肤一致），结果 accent/busy 在它上面只有
**4.27 / 4.29，两项测试当场挂红**。两个色必须与底**一起定**——这是本轮唯一一次
"写完就红"，改底色（提到 `#F1EEE8`，与 `--ux-page` 亮度差 0.032，弹层仍有层次）
比连压两个强调色更保色相。修完 78 项全绿。

深色面另有一处**口径差异**：原令牌的 `--ux-ink-2/.68`、`--ux-ink-3/.42` 是
**半透明**文字（要在页面上合成），而 `contrast()` 忽略 alpha 直接按 RGB 算 ——
所以给的是**合成到 `--ux-page` 之后的不透明值**（`#A8A6A2` / `#82817F`），
数值不能照抄。faint 按原透明度合成只有 3.66，提到 0.52 再合成才到 5.14 / 4.71。

## 2. A 试点：输入区的形态与动效

### 2.1 新基建 `app/lib/ui/theme/dsh_motion.dart`

一个文件管两件事，后续 P1/P2 的组件都从这里取参数：

- **`DshMotion`**：两根曲线（`ease = Cubic(.2,.8,.2,1)`、
  `spring = Cubic(.34,1.45,.64,1)` —— y 超过 1 是刻意的，那就是"过冲"）、
  四档时长（180/350/550/700ms）、按压缩放 0.92。
  `of()` 按皮肤折算：**像素皮肤时长压到 60%** —— 方角配软弹簧会露馅。
- **`DshGlass`**：`rim()` 分边描边、`capsule()` 玻璃胶囊、`panel()` 玻璃面板、
  `pressable()` 按压包装（按下 ease 压下去、松手 spring 弹回）。

**三处关键换算**（原设计是 CSS，Flutter 里各有不同等价物）：

1. **顶部 1.5px 受光高光**：CSS 是两条 `inset box-shadow`，Flutter 的
   `BoxDecoration` **不支持内阴影** —— 等价物是 `Border` **分边设色**
   （`top: 1.5px 亮色` + 其余 `1px` 描边），立体感原样保留。
2. **按压形变**：原设计是 `scale(1.03, .92)`（横胀纵扁），但 `AnimatedScale`
   **只接受等比 double**，而且本 App 的按钮是 46dp 圆钮，非等比会压成椭圆 →
   统一等比 0.92。将来大胶囊要非等比，走 `Transform` + `Matrix4.diagonal3Values`
   （注释里写清了）。
3. **玻璃渐变只给不压正文的部件**：输入框的底必须**不透明**
   （`fieldFill`，`contrast_test` 钉死"文字压在 fieldFill 上要过 AA"）——
   半透明白玻璃会让键入的字重新和页面渐变糊在一起，那是用户 2026-10-15
   明确反馈过的问题。分工写在 `DshGlass` 的类注释里。

### 2.2 `input_bar.dart` 改了什么

| 处 | 改动 |
|---|---|
| 输入框外壳 | 0.8px 同色平边 → **顶部 1.5px 受光高光** + 1px 描边；聚焦时整圈渐到强调色并带一圈柔光（`AnimatedContainer` 350ms + `ease`，不再瞬间跳变） |
| 边框归属 | `TextField` 的 border 全设 `InputBorder.none`，边框**统一由外壳画** —— 否则外层描边与 `focusedBorder` 会叠出两条线 |
| 发送/停止键 | 主键改**玻璃胶囊**（三段白渐变 + 受光边 + 双层柔投影）+ 按压回弹；**加号键保持实底 + 水波纹**（一排两个都发光会没主次，而且水波纹与形变套在同一手势上会触发两次回调） |
| 模型胶囊 | 同族玻璃化 + 按压 |
| 语音键 | 松手回弹走 `spring`（过冲一下再落位），按下走 `ease`（干脆） |
| 结构 | `StatelessWidget` → `StatefulWidget`（内部持有 `FocusNode`）：聚焦动画要知道"有没有在输入"，而这不该让调用方（chat_page）多管一个 focus |

**几何一律没动**：胶囊 46dp、按钮直径 46dp、模型按钮在输入框**下方**的次序 ——
这些是设计稿 OCR 坐标的硬证据，改几何要重新读图，超出本轮范围。

**顺带确认**：DSH Go 的"生成中发送键变停止"这条，本 App **本来就具备**
（`running ? stop : send`），不需要改。

### 2.3 消息卡片 / 加载态

消息卡片沿用既有的 `DshColors.panel(color: …)`（半透明 + 1px 边 + 圆角 + 光晕），
本轮**没有**把它们换成 `DshGlass.panel` —— 理由：`panel()` 是全 App 级装饰，
换它等于动 65 个 UI 文件，超出"先试点会话页"的批准范围（见 §7）。

## 3. P1-1：消息长按菜单

### 3.1 能力与语义

| 消息 | 菜单项 |
|---|---|
| 用户消息 | 复制 / 引用 / 编辑后重发 |
| AI 回答 | 复制 / 引用 / 重新回答（**只对最后一条开放**） |

- **复制**：写剪贴板 + 1 秒 SnackBar 回执（`copyWithSnack`，两处共用一个工具，
  免得改一处漏一处）。
- **引用**：以 `> ` 前缀填回输入框、光标落末尾 —— 引用是**准备**动作，
  用户还要补自己的话，不自动发。
- **编辑后重发**：填回输入框，**原消息先留着** —— 一填回来就删等于"手滑一下
  原话就没了"；发不发由用户决定。
- **重新回答**：清掉本轮半截输出，把最后一条用户消息重发一次。
  历史消息来自 `_resumedHistory` 删不掉，但 `_mergedMessages` 的去重是
  **live 优先**，重发同文本时历史那条会被跳过 → 渲染仍只有一条，不出双胞胎。

### 3.2 两个实现要点

1. **长按包在 `SelectionArea` 外面**：内层选区长按与外层菜单长按在同一个手势
   竞技场里竞争，包在外面才拿得到菜单。代价是正文不再能长按进选区 ——
   当初加选区是为了解决「对话无法复制」，现在**复制由菜单覆盖**，这条退路不丢。
2. **四个回调全部可选**：不传就不显示对应菜单项，于是"菜单里有个点了没反应的项"
   从结构上不可能发生，而不是靠每个调用方记得传齐。

### 3.3 弹层形态

底部弹层（`showModalBottomSheet`）而不是 `PopupMenu`：会话页是单手主战场，
气泡在屏幕中部，长按后手指已离顶部很远；底部弹层落在拇指区，且与本 App 既有的
公告 / 附件 / 模型选择弹层同一套语言。底色显式传 `surfaceStrong`（**必须不透明**，
用户 2026-10-12 反馈过"弹出面板透明度太高"），点任一项**先关弹层再执行回调**
—— 顺序反了会把 SnackBar 抢在弹层动画后面，看着像"点了没反应"。

## 4. P1-2：发送键长按选发送方式

### 4.1 只做协议真支持的两种

| 模式 | 行为 |
|---|---|
| **排队：本轮结束后发送** | 存 `_pendingSend`，本轮结束的链路末尾接着发，发之前给一条 SnackBar |
| **中断并发送** | 先 `session/cancel`，本轮结束时同样由 `_pendingSend` 接着发 |

**刻意不做「插话」**：ACP 同一会话只允许一个 prompt 在飞 —— 运行中再发会回
`Invalid params: a prompt is already in flight for this session`（缺陷 D 记录过
这条，设备日志里出现过 4 次）。"不打断地塞一句"在这条协议上**根本不存在**；
给一个点了必然报错的选项，比不给更糟 —— 这是本项目的"占位即占位"红线。

### 4.2 接线

- `InputBar` 新增 `onSendLongPress`，只传给主键（发送/停止）；
- `DshGlass.pressable` / `PressDetector` 补 `onLongPress` 透传；
- `chat_page` 传 `_running ? _openSendModeMenu : null`（空闲时长按不弹 ——
  短按就是发送，没有第二个语义）；
- flush 挂在**本轮结束方法的末尾**（usage 记账之后），此时 `_running` 已被置回
  false，`_send()` 的门禁过得去。

## 4.6 玻璃拟态：把泡泡白/泡泡夜做成"换形态"（2026-11-14）

用户回了一个「3」，对应我给的三个方向里的第三档：**玻璃拟态**（真模糊层叠 +
高光边 + 悬浮卡片 + 快速弹入）。这一节是执行记录。

### 4.6.1 为什么只改 `DshGlass` / `DshMotion`，不改 `DshMetrics` 常量

上一轮判词是「这俩泡泡主题变化不大」，根因是 `DshPalette` 只有颜色字段，形态由
`DshMetrics` 的全局常量为准。但把那些常量改成 getter 会**当场编译不过** ——
有 38 处把它们写在 `const` 表达式里（`const EdgeInsets.all(DshMetrics.pagePad)`）。

所以走低风险路线：玻璃的三样差异（模糊、描边、投影、动效）**全部集中在
`DshGlass` + `DshMotion`**，这两个类是纯函数/静态构造，没有 const 上下文依赖。
`DshMetrics` 只加一个 `glassStyle` 总闸 getter，不动任何常量。

### 4.6.2 四项改动

| 项 | 实现 |
|---|---|
| 真模糊 | 新增 `DshGlass.surface()`：`BackdropFilter` + `ClipRRect` + `TileMode.clamp` |
| 渐变高光边 | `_GlassShell`：外层画左上亮→右下暗的渐变，只露 1.2dp 作"描边"（Flutter 拿不到渐变描边，这是等价做法） |
| 悬浮卡片 | `_softShadow()` 玻璃档改三层投影（远柔 56 / 中 18 / 近锐 5） |
| 快速弹入 | `DshMotion.of()` 玻璃档 120/220/320/380ms（默认 180/350/550/700），弹簧过冲不变 |

### 4.6.3 性能分级（关键取舍，写进注释了）

`BackdropFilter` 每帧要对背后已绘制像素做高斯模糊，代价随面积线性上涨。所以：

- **真模糊**只给"同屏 1~3 个、长期可见"的面 —— 底部导航、`DshGlassCard` 面板；
- **列表里的卡片**（消息气泡、全 App `DshColors.panel()`）走**伪玻璃**：
  更淡的半透明底 + 更亮的白描边 + 三层悬浮投影，**不逐帧模糊**。

理由写在 `DshMotion` 的类注释里，防止后人"顺手给卡片也加 blur"把帧率打穿。

### 4.6.4 互斥约束

玻璃拟态（`glassStyle`）与像素风（`pixelStyle`）**互斥**，混开会让两个类各自取到
互相矛盾的档位。已加两条测试钉住：① 只有泡泡白/泡泡夜是 glassStyle；
② `DshMetrics.glassStyle` 跟着 `applySkin` 走（页面不许自己判皮肤 id）。

## 8. 本周期踩到的坑（留给下一个人）

1. **`AnimatedScale` 只接受等比 double**，没有 `Offset.one` / `Offset.all`；
   非等比形变要 `Transform` + `Matrix4.diagonal3Values`。
2. **次级底与强调色必须一起定**：先定色再定底，会在更实的底上掉出 AA（4.27）。
3. **`BoxDecoration` 不支持内阴影**：CSS 的 `inset box-shadow` 在 Flutter 里的
   等价物是 `Border` 分边设色。
4. **长按菜单与 `SelectionArea` 抢手势**：菜单必须包在选区**外面**。
5. **纯赋值 `_input.text = …` 不触发 listener**（`initState` 里 `initialText`
   那段注释早写过）：引用 / 编辑回填后必须自己补 `_hasInput`，
   否则填进去了按钮还是麦克风。
6. **三张语言表条数守卫是硬数字**：每加一条 `tr('…')` 都要三表各加一次并
   改 `i18n_test` 的期望值（本轮 `2141 → 2143 → 2147 → 2150`）。
