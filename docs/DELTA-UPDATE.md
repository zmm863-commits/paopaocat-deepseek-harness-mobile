# 差分更新（DSHDELTA v1）

> 2026-10-21 起生效。目标：把每次更新的下载量从 **~99 MB** 降到 **~5 MB**。
> 实测：0.77(117) → 0.78(124) 的补丁 **5.19 MB = 整包的 5.3%**，拼装耗时 **2.2 秒**，
> 拼出来的包与整包**逐字节一致**（sha256 相同）。

---

## 一、它是什么（以及不是什么）

* **是**：发布时拿「上一版 APK」和「这一版 APK」算一个**差异文件**；手机下载差异，
  用**已装的那个 APK** 当底板，本地拼出新包，校验通过再安装。
* **不是**「逐版打补丁」的链条：补丁是**旧包 → 最新整包**的一次性差异，
  跨几个版本都不影响结果（拆出来的永远是最新那份完整包）。
* **不碰**运行环境/引擎/安装方式：运行环境仍在包里，安装仍走系统安装器。

## 二、格式（`DSHDELTA1`，全部小端）

```
magic   "DSHDELTA1"            9 字节
u32     headerLen
header  JSON(utf8)             { format, oldSha256, newSha256, oldSize, newSize, ops }
ops     zlib(操作流)
          0 = COPY: u64 offset, u32 len    （从旧包拷）
          1 = ADD : u32 len, bytes         （新内容）
```

为什么自己定格式、不用 bsdiff：
① bsdiff 补丁是 bzip2，Dart 侧要额外引解压库；这里用 **Dart 自带的 zlib**，不引依赖；
② 不需要 NDK / C 编译 / ABI 适配；③ 头里带两个哈希，天然可校验。

为什么按**内容分块**（CDC，滚动哈希 + 4~64 KB 变长块）而不是固定块：
APK 是 ZIP，一处插入就让后面全部位移；固定 4 KB 块比对会"100% 都变了"（实测过）。
CDC 的切点由内容决定，位移不影响，只把真正变化的块算成新增。

## 三、发布怎么做（出包之后）

```sh
# 1) 生成补丁 + 打印 patches[] 片段（补丁放在 dist/patches/）
node install/release-delta.mjs dist/<新包>.apk \
  https://github.com/<user>/<repo>/releases/download/v<版本> \
  dist/<上一版>.apk [dist/<更早一版>.apk ...]

# 2) 把打印出来的 patches[] 合并进 update.json
#    ⚠️ 补丁文件必须和整包一起上传到同一个 Release（URL 就是上面那个根地址）
```

脚本写死的规矩：
* **补丁 > 整包 60% 就不发**（省下的流量不值得"拼装+校验"的风险）；
* 每个补丁只对它那一个旧包有效（`fromSha256` 精确匹配）；
* 一般只对**最近 1~2 个版本**出补丁；更老的用户直接下整包（功能完全一样）。

## 四、App 侧的流程与三条底线

1. 拿已装 APK 的路径（原生 `applicationInfo.sourceDir`）→ 算它的 sha256（算一次缓存）；
2. 在清单 `patches[]` 里找 `fromSha256` 完全匹配的那一条；没有 → **整包**；
3. 下载补丁（复用整包下载器：进度/断点/sha 校验）；
4. `DeltaPatch.apply()` 拼装，并做三道校验：
   * 旧包哈希 = 补丁认的那个；
   * 拼出来的**大小** = 头里的 `newSize`；
   * 拼出来的**哈希** = 头里的 `newSha256`；
5. 过 → 交给已有的签名校验 + 安装流程；**任一条不过 → 删掉半成品、回退整包下载**。

> 增量失败**永远不会**变成"更新失败"——它只是少省一点流量。

## 五、常见问题

| 现象 | 原因 | 结果 |
|---|---|---|
| 没走增量，直接下整包 | 装的是测试包/改过的包，或我们没留那个基准 | 正常（功能一样） |
| 补丁下载到一半断了 | 网络 | 断点续传（同一个下载器） |
| 拼装报"哈希不符" | 补丁与旧包不是一对（极少） | 删半成品，回退整包 |
| 安装后版本没变 | 系统安装器被用户取消 | 与整包同一条路径，无差别 |
| 空间不够 | 拼装需要额外 ~100 MB 临时空间 | 安装失败 → 用户清理后重试整包 |

## 六、代码地图

| 文件 | 作用 |
|---|---|
| `install/make-delta.mjs` | 生成补丁（CDC + zlib） |
| `install/release-delta.mjs` | 出包时批量生成 + 打 `patches[]` JSON（含 60% 阈值） |
| `app/lib/local/delta_patch.dart` | 补丁头解析、拼装、三道校验 |
| `app/lib/ui/pages/settings_tab.dart` | 更新流程：先试增量、失败静默回退整包；卡片显示「增量 X MB」 |
| `app/lib/local/update_checker.dart` | `patches[]` 解析（容错）、`patchFor(已装包哈希)` |
| `app/test/delta_patch_test.dart` | 5 条回归：正常拼装 / 旧包不符 / 补丁截断 / 大小不符 / 格式不对 |
| `app/tool/verify_delta.dart` | 开发用：拿真实两个包验证"逐字节一致" |
