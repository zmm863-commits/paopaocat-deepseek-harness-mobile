# 0.81 进化方案：设计站 + 电脑访问

- 产生时间：2026-10-28
- 范围：`dsh-mobile` 的「电脑访问」（手机当主机给电脑用）+ 内嵌设计站
- 方法：代码审计 + 真机实测取证（moto razr 60 Ultra / Android 16 / 0.80+226 完整包）
- 结论先行：**有 1 个必须立刻修的安全漏洞，2 个影响日常可用性的硬伤，其余是体验与体积优化**

## 二、P0：设计站端口**完全没有鉴权**（必须本周修）

### 事实

设计站那条转发端口（当前 `42195`）对局域网完全开放，**不需要任何凭据**：

```
GET /agnes-studio/api/models              → 200   （可用模型清单）
GET /api/vendors                          → 200   （手机配了哪几家）
GET /agnes-studio/api/library/list        → 200   （资料库全部文件名）
GET /agnes-studio/api/library/file?path=shots/stop3.png
                                          → 200，155,495 字节真图下载成功
```

对照组：DSH 自己的端口对同一请求返回 **401**。也就是说**安全等级差了一整级**。

### 影响

手机连到任何共享网络（公司 Wi-Fi、咖啡厅、酒店、朋友家）时，同网段任何人：

1. 用**机主的 Key** 调用大模型 —— 直接花钱，且账单记在机主头上；
2. 浏览并下载机主资料库里的**全部文件**（设计稿、截图、工作文档）；
3. 往资料库写文件（`/library/save` 无鉴权）。

这是目前最严重的问题，**优先级高于任何功能**。

### 根因

`server/index.mjs` 里早就有一层口令门：

```js
const ACCESS_TOKEN = (process.env.ACCESS_TOKEN || '').trim()
function denied(req) {
  if (!ACCESS_TOKEN) return false   // ← 没配就完全放行
  ...
}
```

但我们启动后端时**没有设 `ACCESS_TOKEN`**，于是这道门等于不存在。

### 改法（改动面很小）

1. App 侧：开关「电脑访问」时生成一个随机口令（32 位），存内存 + 诊断日志前缀（不落盘明文）；
2. 启动 agnes 时注入 `ACCESS_TOKEN`；
3. 带口令的 URL 拼进「复制网址」和跳转按钮，例如
   `http://192.168.3.7:42195/?token=<口令>`；
4. 后端 `denied()` 增加：URL 带 `?token=` 且匹配 → 下发 cookie（与 DSH 同款交互）；
5. 关闭开关时立刻让口令失效。

**验收**：不带 token 访问 `/agnes-studio/api/models` 必须 **401**；带 token 才是 200。
（与 DSH 那条的判据完全一致：403→401 是围栏，401→200 是凭据。）

**工作量**：约 1 小时（后端 20 行 + App 30 行 + 拼 URL 3 处）。

## 三、P1：没有前台服务，后台会被回收

### 事实

`AndroidManifest.xml` 只有两个 service：`DshSchedulerService`、`VdShellPairingService`。
**没有任何服务托管 DSH 与设计站这两个 node 进程。**

### 影响

- App 切后台久了 / 内存紧张 / 用户从最近任务划掉 → node 进程被杀；
- 电脑那边表现为**页面突然 502、设计站打不开**，而且用户完全不知道为什么；
- 现在的「30 秒健康巡检」只能救「进程还在但假死」，救不了「整个 App 被回收」。

### 改法

新增 `WebBridgeService`（前台服务）：

- 随「电脑访问」开关启停；
- 通知栏常驻一条：「电脑正在访问 · DSH + 设计站」，点开回到设置页；
- `START_STICKY` + `PARTIAL_WAKE_LOCK`（仅在开关打开期间）；
- 服务里持有两个 `PortForwarder` 与 `AgnesWeb`/`BotServer` 的生命周期引用。

**验收**：开关打开后把 App 划掉再等 5 分钟，电脑端仍能刷新页面。

**工作量**：约 3~4 小时（Kotlin 服务 + Dart 侧桥接 + 权限）。

## 四、P1：端口每次都变，URL 无法记住

### 事实

`_designForward.reservePort()` 与 `PortForwarder.reservePort()` 每次开关都重新挑端口。
实测出现过 40731 / 38385 / 42633 / 39885 / 42195 / 40945…… 全是新的。

### 影响

- 用户每次都要回手机点「复制网址」；
- 电脑上收藏的链接失效；
- 口令方案（P0）也要求 URL 相对稳定，否则记不住。

### 改法

- 固定端口段：首次从 `38000–38999` 挑一个空闲的**写进设置**，之后优先复用；
- 被占用时顺延，并把实际端口写回设置；
- 设置页显示「固定地址」，允许用户手动改端口。

**验收**：连续开关 3 次，「复制网址」里的端口不变。

**工作量**：约 2 小时。

## 五、P2：首启 70~80 秒

### 事实

| 阶段 | 耗时 |
|---|---|
| 解包 `studio-site`（8.4MB / 66 文件）+ `agnes-server`（304KB） | 约 10~20 秒（首次） |
| DSH 冷启（插件树） | 约 20~25 秒 |
| agnes 冷启 + 等 `/healthz` | 约 5~10 秒 |
| 目前是**串行**的：先起 DSH，再起 agnes | 累加 |

### 改法

1. **并行**：解包与 `AgnesWeb.ensureStarted` 可以和 `BotServer.ensureStarted` 同时跑（两者互不依赖）；
2. **预热**：App 首次安装后的引导流程里就把资产解包好（用户配模型的时间里顺手做完）；
3. **进度可见**：现在只有一个转圈，改成「正在解包 → 正在启动 DSH → 正在启动设计站」三行状态。

**验收**：第二次及以后开关，两个服务都就绪 < 25 秒。

**工作量**：约 2 小时。

## 六、P2：体积 —— `design/` 子站占 57%

### 事实

```
assets/studio-site        8.4 MB
├── design/               4.8 MB   ← Next.js「设计工作站」子站，占 57%
├── img/                  2.2 MB
├── studio.js             1.2 MB
└── 其它                  0.2 MB
```

`design/` 是完整站首页里 iframe 嵌的那个「泡泡猫设计工作站」（Next 导出，自带 `_next` 资源）。

### 判断

- 若这个子站已经由主站入口覆盖、或用户不用 → **删掉省 4.8MB 资产**（APK 约省 2MB）；
- 若要保留，可以只保留首屏需要的 chunk，其余按需。

### 需要你定

**这个「设计工作站」子站还要不要？** 我倾向「先问」——它可能是你早期做设计稿的工具，现在主站 15 个模块里没有它的等价功能。

## 八、P3：体验优化（可选）

1. **二维码**：手机屏显示二维码，电脑扫一下就打开（省掉复制粘贴）。
   实现成本低（`qr_flutter` 已在依赖里？需确认），体验提升明显。
2. **设置页入口前置**：现在藏在「设置 → 应用 → 电脑访问」，可以提到「设置」一级，或加到首页快捷区。
3. **连接历史**：记住最近用过的 IP + 端口，换电脑时一键切换。
4. **断开提示**：电脑端检测到 502 时显示「手机上的服务已停止，请在手机上重新打开电脑访问」而不是白屏。

## 九、P3：资料库扫描上限

`listLibrary` 手机模式从工作区根递归，限制 `depth ≤ 4`、`≤ 4000 项`。
工作区堆到几千个文件后会**静默截断**（`truncated` 标记目前界面没显示）。

改法：界面显示「已显示前 N 项」，并提供按目录/类型筛选。

## 十、排期建议

| 版本 | 内容 | 预估 |
|---|---|---|
| **0.81（必须）** | P0 鉴权 + P1 前台服务 + P1 固定端口 | 6~7 小时 |
| **0.82** | 首启并行化 + 进度可见 + 死代码清理 | 3~4 小时 |
| **0.83** | 二维码 / 入口前置 / 断开提示 / 资料库截断提示 | 4~5 小时 |

**为什么不把 P0 单独出包**：鉴权改动会动到 URL 形态（加 `?token=`），
而固定端口（P1）会再动一次 URL。两件事合在一个包发，用户只需要换一次链接。

## 十一、风险与取舍

| 项 | 风险 | 处置 |
|---|---|---|
| 加鉴权后老链接失效 | 用户电脑上收藏的旧 URL 全 401 | 版本说明里写清楚「升级后重新复制网址」 |
| 前台服务常驻通知 | 用户可能觉得吵 | 通知可折叠、文案写「电脑正在访问」，关开关即消失 |
| 固定端口被占用 | 极少数情况下顺延 | 自动顺延并提示实际端口 |
| 删 `design/` 子站 | 可能删掉仍在用的功能 | **先问用户**，不擅自删 |

---

## 十二、一句话总结

**能用，但现在是「开放模式」在跑** —— 同一个 Wi-Fi 下的任何人都能用你的 Key、翻你的文件。
先把 P0 的门装上（1 小时的事），再做保活与固定端口，这套才敢在别人的网络里打开。

其余都是锦上添花，按 0.82 / 0.83 慢慢来。
