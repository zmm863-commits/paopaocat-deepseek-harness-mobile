# 泡泡猫 DSH 手机版 · 0.81（开发记录）

> 2026-10-30 开始 · 基线 0.80（248）→ 本次 **249**
> 主题：**把「手机当主机、电脑当屏幕」这条路收口** —— 断了看得懂、等的时候看得见、打开少打字；

## 一、这一版为什么是这些内容（范围依据）

`docs/PLAN-0.81-设计站与电脑访问.md`（2026-10-28 审计取证版）里排过三档：

| 原排期 | 内容 | 实际 |
|---|---|---|
| 0.81 | P0 设计站端口鉴权 + P1 前台保活 + P1 固定端口 | **提前在 0.80 里做完了**（提交 `4b297d5`） |
| 0.82 | 首启并行化 + 进度可见 + 死代码清理 | 并行化也在 0.80 做了；**进度可见留到本版** |
| 0.83 | 二维码 / 入口前置 / 断开提示 / 资料库截断提示 | 本版取**断开提示 + 扫码**；截断提示 0.71 就已有 |

所以 0.81 的实际范围 = **原 0.82/0.83 里还没做的 + 0.80 发布时留下的三处缺陷**。
不重复做已经做完的事，也不为了「填满一个版本号」去改能用的东西。

## 二、六项改动（逐项）

### 1. 电脑端断线不再是白屏（新）

`lib/local/port_forwarder.dart`

以前上游连不上就 `client.destroy()` → 浏览器一片白或 `ERR_EMPTY_RESPONSE`。
现在转发层自己回一页 **HTTP 502 + 中文说明**：

- 写清三个常见原因（开关关了 / App 被回收 / 换了网络）；
- 写清去哪儿重新打开（`设置 → 移动桌面平台`）；
- 页面里每 3 秒 `HEAD` 一次自己，**只要不再是 502 就自动 reload** ——
  手机一恢复，电脑这边不用手动刷新；
- 判据刻意是「不是 502」而不是「200」：手机刚回来的瞬间上游可能是 401/404，
  那也说明服务活了；
- 不引用任何外部资源（此刻手机可能连网都没了，CDN 一定加载不出来）。

诊断日志节流 60 秒一条（页面自己每 3 秒还会探一次，不然日志会被刷满）。

### 2. 开关过程看得见（新）

`lib/ui/widgets/computer_access_panel.dart`

四段人话 + 已等秒数：
`准备运行环境… → 正在启动 DSH 与设计站… → 正在打开对外端口… → 正在接上设计站…`

用枚举 `_Stage` + `stageText(context)`，**每段都写成 `context.tr('字面量')`** ——
i18n 扫描器只认这个形状；把文案塞进 String 字段再 `tr(_stage!)` 会永远进不了翻译表
（切外语露中文且不报错，项目里踩过同类坑）。

### 3. 扫码打开（新）

`lib/ui/widgets/computer_access_qr.dart`（新文件）+ 面板上的「扫码打开」

一屏给出：二维码 + **能照着敲的大字地址**（`192.168.x.x:端口`）+ 单独一行的 `/?token=…`。

为什么不只给二维码：笔记本有摄像头且装了扫码工具才行，台式机根本没有摄像头。
所以文案写的是「电脑有扫码工具就扫这个码；没有的话照着下面手打」——
不写「扫一下就行」这种半真半假的承诺。

依赖：`qr_flutter ^4.1.0`（纯 Dart，无原生库，不影响 ABI）。

**同一轮里测出来的真 bug（已修）**：两个地址（DSH 网页 + 设计站）同时给的时候，
对话框内容比一屏高，在 800×600 的测试屏上直接报 `RenderFlex overflowed by 21 pixels`
—— 真机小屏 / 横屏会看到黄黑条。content 包了 `SingleChildScrollView`。
这条不是「测试写错了」，是界面真会坏；`test/computer_access_qr_test.dart` 的四个用例
现在同时充当回归。

### 4. 修掉：设计站起不来会把保活服务一起停掉（0.80 引入）

0.80 的 `_apply()` 里，`await WebBridge.stop();` 写在了「设计站启动失败」的
catch 块**里面**（缩进都是乱的）。后果：设计站起不来时，DSH 网页本身还活着，
却把保护它的前台服务停了 → 系统随后回收整个进程 → 电脑端断开。

现在：保活只在**用户自己关开关**时停（挪到 else 分支），catch 块里写明为什么不能停。

### 5. 修掉：英/日/韩界面里「移动桌面平台」整块还是中文（0.80 漏翻）

`check-tables.mjs` 实测 0.80 发布时漏翻 **23 条**（整个「移动桌面平台」面板 +
设置页的组名）。都是 0.80 改名时新写的文案，没进三张表。

本版：补 84 条译文（28 条 × 3 语言），`check-tables` **2032 / 2032 · 0 漂移**，
`i18n_test.dart` 钉住的条目数 2004 → 2032。

### 6. 修掉：App 里的 0.80 更新说明只有 5 条

`changelog.dart` 里 0.80 那条停在开发中途的「网页版做减法 5 条」，
而发布说明是 10 条 —— 用户装完在「关于 → 更新说明」里**看不到「移动桌面平台」这个主角**。

现在补齐到 10 条（口径与 `docs/RELEASE-0.80.md` 一致），日期补 2026-10-29。

状态（见 `docs/HARMONYOS-ROUTE-A-DOWNGRADE.md` §附录 B）：

`Platform.operatingSystem == 'ohos'` 在 Android 上恒 false）。等鸿蒙线复活的
那个周期再单独收口、单独出 HAP。

## 八、已知遗留（如实）

- **扫码对台式机无效**：没有摄像头就扫不了，所以同时给了大字地址；这条不是 bug，是场景限制。
- **首启仍要等 40~80 秒**：并行化 0.80 已做，剩下的耗时是解包（8~20s）+ DSH 冷启（20~25s）。
  真要再快得做「装完就在后台预热」，那是 0.82 的事。
- **本地 `update.json` / `notice.json` 落后线上两个版本**（本地停在 0.78 / 0.76）：
  0.79、0.80 两次发布是直接推线上、没回写本地。本版发布时一并同步，避免下次拿错基线。
