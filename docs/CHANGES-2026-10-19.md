## 一、Bot 上手机（构建号 78~108，前半天）

方向定案：**Bot 页面用 WebView 跑 dsh web + ds-bot**（要求「体验和桌面版一样」；
用 Flutter 重写它那 826 条文案的前端不可能追平）。中间走过一段弯路
（改用原生聊天页，构建号 81）后按用户实测「网页版可以跑通」回到 WebView（102）。

关键结论都记在 `docs/BOT-TEST.md`，这里只留三条最容易再踩的：

1. **`--patch` 必须留在 `--no-open` 之前**。`dsh` 的 launcher 只认自己的参数，
   一旦出现它不认识的 token，**后面全部**算作 profile 内 app 的参数 → 写反顺序时
   `--patch` 被 web app 当成未知选项，直接 `error: unknown option '--patch'` 退出
   （退出码 1，界面报「Bot 服务没能起来」）。
2. **mobile runtime 不能直接在本机跑**：要先按手机的做法覆盖两个 shim
   （`node-addon-require-builtin`、`node-addon-system/flock`）并加 `--expose-internals`。
3. **`MainActivity.unpack` 只认 `app/` 与 `shims/` 两个前缀**，其余条目一律丢弃 ——
   任何新的随包资源必须挂在 `app/` 下。

## 二、「发给：」浮层在手机上被挤成一条

### 用户报的现象
「点 + 只看到几个图标、看不到建群」→ 用户确认是**「发给：和谁聊…」面板** →
再补一句「就是画圈的这个地方展不开」。

### 怎么读到那张图的（视觉后端全挂时的替代手段）
本轮 `vision_describe` 的两个后端都 TIMEOUT、当前模型也无 image input，
于是走了**本地像素分析 + 子代理 OCR**：

- `ffmpeg -f rawvideo -pix_fmt rgb24` 把截图拉成裸像素，Python 找高饱和红笔迹
  （#FA5151）→ 连通块包围盒 = 用户画的圈：
  **x 897–1223、y 458–1247**（1224×2992 的图）。
- 圈内只有 4–5 个 30–40px 的小图形沿一列排下、**旁边零文字**；x≈1117 有一条浅灰细竖线。
- 「发给:」在 x957–1064、其右的「+」在 x1110–1156。

结论与代码推导一致：**整个浮层被压在屏幕右边一条里**。

### 根因（两层叠在一起）
1. **108 版注入的 CSS 从来没生效过**：`_mobileFitCss` 里 `].join('` 后面写入的是
   一个**真换行**（本意 `'\n'`）→ `node --check` 报
   `SyntaxError: Invalid or unexpected token` → 整个 IIFE 不执行，一个 `<style>` 都没插。
2. 就算生效也瞄错了容器。真正被挤扁的是 ds-bot 的 `.bt-pane`：
   `position:fixed; right:0` + 组件内联 `left = usePaneLeft()`
   （取 `[class*="_footArea"]` 父元素的 `getBoundingClientRect().right`）——
   手机上这个差几乎为 0；里面的 `.bt-drop` 又是
   `width:min(550px, calc(100% - 64px))` → 被算成几十像素 → 每行只剩图标、
   文字被 `text-overflow:ellipsis` 吃光。

### 修法
按**真实类名**精确改（不改 ds-bot 源码，它随 runtime 分发，App 侧注入最省事）：

```css
.bt-pane        { left:auto !important; right:0 !important; width:min(100vw,440px) !important; }
.bt-pane .bt-drop { left:8px !important; width:calc(100% - 16px) !important; }
[role="menu"],[role="listbox"],.bt-menu,.bt-drop { max-height:min(420px,60vh) !important; overflow-y:auto !important; }
```

⚠️ **教训**：这段 JS 必须过 `node --check`；多行 CSS 改用**反引号模板字符串**承载，
Dart 原始字符串里就再也不需要 JS 转义，这类错犯不出来。

## 三、Bot 页留痕 + Bot 模式完全权限（构建号 109）

### ① 留痕（用户：「把这里的操作，都添加日志痕迹」）
原来只记服务端那几件事，**网页内部一个字都没有** —— 而"点 + 没反应""浮层展不开"
恰恰发生在网页侧。现在两边都记：

- `dshBotLog` JavaScriptChannel + 注入脚本回报：点了什么（`.bt-plus` / 菜单项文字 /
  `.bt-pane` 内）、量到的尺寸（`.bt-pane`、`.bt-drop` 宽高 + `[data-composer-card]`
  里到底有没有 `input[type=file]`）、文件输入框 change、**网页自己的 JS 报错**
  （108 那条语法错就是因为没有这条才漏掉）。页面 1.2s / 4s 各自动量一次。
- App 侧补记：打开/离开 Bot 页、服务就绪、地址变化、返回键分支、手动停服务、
  注入成功（含字符数）/失败、主文档加载失败。
- ⚠️ WebView 地址里带 **token（能力令牌）**，**一律不写日志**。

### ② 完全权限：一个顺序 bug + 两道保险
**真 bug**：`--patch` 在拼 args 时按 `runtime.hasModelConfig` 有条件加，而
`hasModelConfig` 的定义就是「overlay 文件是否存在」；可「确保 overlay 存在」那句
排在 args **之后** → 覆盖安装/清数据后第一次进 Bot 页时 overlay 还不存在 →
**一份 patch 都没传** → 权限预设一起丢 → 退回 `workspace-write` + `approval: ask`
→ Android 上没有沙箱后端 → 每个工具调用都要用户批准（真机原话
「一直出现 agent 请求执行操作」）。**注释当初写对了，位置错了。**

修法：
- `_ensureOverlay()` 移到拼 args **之前**；
- 新增 `_ensureFullAccessPatch()` → `bot-full-access.patch.yml`
  （`sandbox-policy.mode` + `permission.defaultPreset` 均 danger-full-access），
  起服务时**无条件 `--patch` 且放最后**（dsh launcher 可重复收集、按 argv 顺序叠加，
  后者生效 —— 见 `dsh/lib/bin.js` 的 "Repeatable single-value collector"）；
- 再加环境变量 `DSH_PERMISSION_MODE=danger-full-access`（`dsh-base` 的
  `@deepseek-ai/dsh-user-approval` policy 就是从这个变量算的：
  `(process.env.DSH_PERMISSION_MODE ?? 'workspace-write') === 'danger-full-access'
   ? 'never' : 'ask'` → 不设就是 ask）；
- 启动时记一行「带了几份 patch」（0 份 = 权限一定回退）。

### 本机证据（可复跑）
```bash
DSH_HOME=/tmp/dumpcheck dsh bottest --patch /tmp/bot-full-access.patch.yml --dump-config
```
- **不带** patch：`permission.config` 只有 presets 定义、**没有 `defaultPreset`**；
  `approval.policy` 算出 `'ask'` → 即"每个调用都要批准"的状态。
- **带上** patch：`sandbox-policy.config.mode: danger-full-access` +
  `permission.config.defaultPreset: danger-full-access`（dump 里标注
  `patched by …bot-full-access.patch.yml`）；`permission-presets` 内部会调
  `setApprovalPolicy('never')`（preset 表原文：full file access without approval prompts）。

## ① 设置对话框在手机上「几乎无法使用」+「顶部按钮重叠」
**真因（硬编码的桌面布局）**：`ds-bot/client.js` 里

```css
.bt-settings      { --bt-set-w: min(1100px, calc(100vw - 48px)); display:flex; }
.bt-settings-nav  { width: 198px; flex: none; }          /* 页面列表 */
.bt-settings-main { width: calc(var(--bt-set-w) - 198px); height: var(--bt-set-h); }  /* ← 硬编码 */
```
手机上 `--bt-set-w` = 100vw-48 = **342px** → 正文只剩 **144px**。页面被挤爆，标题与右上角
那个 `position:absolute; top:12px; right:12px` 的关闭按钮**叠在一起** —— 用户说的
「页面顶部有的时候存在按钮重叠」就是这个（正常态不出现，所以"有的时候"）。

**修**：窄屏（≤720px）改成「上面一排可横滑的页签 + 下面整页」：
```css
@media (max-width: 720px) {
  .bt-settings      { flex-direction: column !important; --bt-set-w: calc(100vw - 16px) !important; }
  .bt-settings-nav  { width: 100% !important; flex-direction: row !important; overflow-x: auto !important; border-right: 0 !important; border-bottom: .5px solid var(--bt-line) !important; }
  .bt-settings-main { width: 100% !important; flex: 1 1 auto !important; min-height: 0 !important; }
}
```

## ② 不再开放 DSH(Harness) 的界面（用户：怕用户改乱配置）
ds-bot 里通往它的入口，**四条**（第四条是后门，查源码才发现）：

| # | 位置 | 文案 | 调用 |
|---|---|---|---|
| 1 | 设置抽屉（`.bt-settings-item.bt-settings-shell`） | `Harness 设置` | `openHarnessSettings()` |
| 2 | 模型菜单 | `模型和服务商…` | `openHarnessSettings()` |
| 3 | 定时任务页 | `打开 Harness 设置` | `openHarnessSettings()` |
| 4 | 账号菜单 | `切换经典 Agent 模式` | `actions.setSurface("agent")` |

第 4 条为什么也算：ds-bot 自己的注释 —— `settings.launcher` 那行旁边写着 shell 的设置
启动器「comes back in Agent mode」，也就是切到经典模式后 **DSH 的设置入口又冒出来**。

**修**：CSS 藏 `.bt-settings-shell` + JS 按文案藏（**中英两套**，界面语言不是中文也拦得住）
+ **捕获阶段吃掉点击**（`preventDefault + stopPropagation` → React 挂在根节点上的 onClick
收不到，别的路径也走不通）+ 独占一组的分隔线一并收掉。

## ⑤ 网页主题跟随 App 深浅色
网页（`dsh-client-ui-theme`）的做法是：`preference` 存在**宿主设置**里，默认 `system`，
然后 `body.toggleAttribute('data-ds-dark-theme', dark)` —— 也就是**跟手机系统**，不跟 App。
**修**：注入时按 `DshColors.isLight` 把 `body[data-ds-dark-theme]` 钉住；`MutationObserver`
盯着这个属性（runtime 若重新 publish 会再钉回来）；App 切皮肤时用一段独立的
`_themeJs()` 立刻推过去（不重跑整段 —— 那段有 `__dshBotTrace` 守卫，主题得能反复推）。
