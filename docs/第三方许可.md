# 第三方组件与许可

> 这份文档与 App 内「设置 → 关于 → **第三方组件与许可**」是**同一份内容**。
> GPL 类组件的要求是"随二进制给出许可与相应源码的获取方式"——**藏在仓库里不算**，
> 装机的人要能在 App 里读到，所以两处必须同步。
> **加组件就同步改这两处**（改这里的人请顺手改 `settings_tab.dart` 的 `_showLicenses`）。

最后更新：2026-10-13（新增「本机离线配音」：sherpa-onnx + onnxruntime + seek-bzip；模型按需下载）。

## ffmpeg 7.1（含 libx264）

| 项 | 内容 |
|---|---|
| 用途 | 「影视」页的**口播 / 短剧**：视频拼接、转码、混音、加字幕（`ffmpeg` / `ffprobe`） |
| 版本 | ffmpeg 7.1（官方 release tarball）+ x264（`github.com/mirror/x264` 的 master） |
| 授权 | **GPLv2 或更高版本（GPLv2+）** —— 因为构建时启用了 `--enable-gpl --enable-libx264`，而 libx264 本身是 GPL |
| 是否修改源码 | **未修改**。只做了针对 Android arm64 的交叉编译（含 strip） |
| 许可全文 | https://www.gnu.org/licenses/old-licenses/gpl-2.0.html |
| 相应源码 | https://ffmpeg.org/download.html 与 https://code.videolan.org/videolan/x264 |
| 构建参数 | 见仓库 `install/build-ffmpeg-android.sh`（可复现：NDK 28.2 + API 24 + `--target-os=android --arch=aarch64`） |
| 体积代价 | **解压到手机约 +23.8 MB**；**APK 里约 +10.9 MB**，即 100.7 MB → 约 **111.6 MB**。<br>（早先是**静态双份**方案：两个可执行文件各 ~21.5 MB、合计 42.8 MB / APK +20.6 MB → 121.3 MB。2026-10-11 按用户要求改成**共享库**：`ffmpeg`/`ffprobe` 各 ~0.3 MB，8 个 `libav*.so`/`libsw*.so` 由两个程序共用 → **省 19 MB 安装体积**。soname 必须用 `patchelf` 改成朴素名，因为 jniLibs 只收 `lib*.so` 且 APK 不支持软链。） |

### 实测事实（不是推断）

* `file` 结果：`ELF 64-bit LSB pie executable, ARM aarch64, ..., stripped`，
  interpreter 是 `/system/bin/linker64`（Android 正确形态）；
* `CONFIG_LIBX264 1` —— libx264 确实编进去了；
* `readelf -d` 的依赖**只有 Android 公开 NDK 库**：
  `libm / libandroid / libcamera2ndk / libmediandk / libz / libdl / libc`
  （没有一个是我们自己还要另外打包的库）；共享库版已做过**依赖闭包自检**：
  跨库依赖全部落在随包的 8 个 `.so` 里；
* ⚠️ **这个构建里没有 `subtitles` / `drawtext` / `ass` 滤镜**（NDK 里没有
  libass/freetype，编不进去）。所以**字幕由 App 用 Flutter 画在图上**（手机自带中文字体、
  字形正确），ffmpeg 只负责"图+音频→mp4、拼接"。这也是设计决定，不是遗漏。
* ✅ **功能已在本机验证过**（用 qemu 跑同一个源码编出的**静态**版本，因为动态版需要
  Android 的 `/system/bin/linker64`）：真编了三段视频，再用**电脑上独立的 ffprobe** 校验产物 ——
  `libx264+aac` 编码、**一张图+一段音频→mp4**（口播的典型形状）、`-vf scale`（短剧的形状）
  全部产出合法的 H.264/AAC mp4。完整命令与结果见 `docs/AUDIT-2026-10-09.md` §17.3。
* ⚠️ 仍未测量的只有一件事：**动态版在真机上能否被执行**（本机没有模拟器/真机）。
  出包闸门（`install/check-release.py`）负责"存在 + 必须是 AArch64"，剩下的靠装机验证。

### 为什么它必须"假装成 lib*.so"

Android **不允许从 App 数据目录执行文件**（实测 EACCES），而 Gradle 只把
`lib/<abi>/lib*.so` 打进包并解压到 `nativeLibraryDir` —— 那里才允许执行。
所以：

- 包内是两个 ELF 可执行文件，名字却是 `libffmpeg.so` / `libffprobe.so`；
- 调用方式（两条都通）：
  - 技能脚本里直接写 `ffmpeg -i ...`（exec shim 的 prelude 定义了同名 shell 函数）；
  - 用环境变量 `DSH_ANDROID_FFMPEG` / `AGNES_FFMPEG`（绝对路径；后者是**桌面端影视工具
    插件认的名字**，两边对齐后技能脚本不用分平台改）。

### 出包闸门

`install/check-release.py` 会检查这两件事，**任何一个不满足都不许发版**：

1. `libffmpeg.so` / `libffprobe.so` **必须在包里**（缺了不会崩，而是用户点口播/短剧时
   才 ENOENT —— 那是最难查的一类问题）；
2. 它们必须是 **AArch64** 的 ELF（放错架构等于装上也跑不起来）。
